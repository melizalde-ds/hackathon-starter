# Find an Idea

A great build on the wrong idea loses. Do this before opening an editor.

The idea and data banks live in the **Hackathon Bank** Claude Project, not in this repo. Run the idea finder there so it can pull from them. This file is the method, so any agent can run it too (`/idea`).

## First: which kind of event?

- **Bounties given** → the brief is the idea. Find the angle (below), then `start/pick-a-bounty.md`.
- **Open theme** → generate, then cut (below).
- **Both** (open theme with sponsor tracks) → generate inside the tracks, then use `start/sponsors.md` to stack them.

## Bounties given: find the angle

Most teams build the obvious version. Winners solve the hard part.

1. **Sponsor's real goal.** What do they sell? What would they post about on launch day?
2. **The hard part, in one sentence.** "The hard part is ___." Usually not the search box or the dashboard.
3. **The input flip.** What does the user do by hand today? Make it one input, one answer.
4. **Stacking.** Can the same build qualify for another track? (`start/sponsors.md`)
5. **Ask the sponsor early:** "If I built X, would that win?"

## Open theme: generate, then cut

1. **Start from data or a workflow, not inspiration.** Messy, scattered, or painful data that already exists. Making it usable is the idea. Check the data bank first.
2. **Pull from the idea bank.** Most new ideas are an old pain point plus a new sponsor API.
3. **Generate 15 fast.** Don't judge yet. The good one is usually not #1.
4. **One-sentence test.** "[Specific person] spends [time] doing [task]. With this, they type [X] and get [Y] in seconds." Can't fill it in? Drop it.
5. **Use your edge.** Domains where a judge can't catch you being subtly wrong: Kubernetes and platform work, observability, data pipelines, payments and Fed rails, Rust and WebAssembly.
6. **Score and cut.**

## Your formula

Juan reuses one shape: messy data that already exists → one simple input → a useful answer in seconds.

Yours (draft, refine after each event): a system that's invisible and risky → one view that shows what will break and what to do.

## Done when

- The hard part named in one sentence
