# Pick a Bounty

A wrong pick costs the whole event. If you couldn't win it without AI, AI won't make you win it.

## 1. Collect

For each bounty: brief, rubric, prize, and any data or APIs provided.

## 2. Research

Run `/bounty` (or the Hackathon Bank Project). You want: who the sponsor is, what they care about, what exists already, where the hard part is.

## 3. Check the data

| Source | Public API? | Auth / key | Rate limits | Sample call worked? |
|--------|-------------|------------|-------------|---------------------|
|        |             |            |             |                     |

Data that needs scraping makes it a scraping project. Skip it, or seed it once on Day 0.

## 4. Score honestly

| Bounty | Domain feel | Stack fit | Data exists | Hard part clear | Rubric fits me | Stacks with | Total |
|--------|-------------|-----------|-------------|-----------------|----------------|-------------|-------|
|        |             |           |             |                 |                |             |       |

## 5. Name the hard part

"The hard part of this bounty is ___." Can't write it? You don't understand the bounty yet.

## Red flags

- Picking for the biggest prize or clout
- A domain you have no feel for; the sponsor will spot mistakes in thirty seconds
- A rubric weighted toward something a short demo can't show

Copy the winner into `brief/brief.md`.
